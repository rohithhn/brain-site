MCP memory server: persistent memory for Claude and more

What is an MCP memory server?

A Model Context Protocol server that exposes long-term memory as tools an AI assistant can call. The model asks it things like "what did we decide about caching?" and gets back the few memories that matter.

The Model Context Protocol (MCP) is an open standard for connecting AI applications to tools and data. An app that speaks MCP (a "client") can talk to any MCP "server" you register, without custom integration code. That makes MCP the one place you can plug a single memory into many different assistants at once.

What does a memory MCP server expose?

A handful of tools, each with a short description the model reads.

Recall

Search memory for what's relevant to a question, ranked, and return the top few.

Load context

Hand over the briefing for the current project: decisions, conventions, open issues.

Save

Write a new decision, preference or fix so later sessions know it.

Skills

List and load reusable procedures the user has taught before.

The descriptions matter more than they look. The model decides whether to call a tool by reading them, so a vague description means a tool that never gets used.

Push vs pull memory: what's the difference?

Push puts memory in front of the model automatically. Pull waits for the model to ask.

PushPull (MCP)
How it arrivesWritten into a file or prompt the tool always loadsReturned when the model calls a tool
ReliabilityAlways presentOnly if the model decides to ask
FreshnessSet at session startSearched live, mid-session
DepthA short briefingCan dig for specifics on demand
Works inTools that auto-load an instructions fileAny MCP client, desktop apps included

Pull alone has a well-known failure mode: the model is confident, doesn't think to check, and repeats the mistake memory would have prevented. Push alone can't answer the specific question that comes up halfway through a task. The reliable setup uses both: a short pushed briefing at session start, and an MCP server for everything deeper.

Which apps can use an MCP memory server?

Any app that supports MCP. For AI coding, that's most of them.

  • Claude Code, Codex, Cursor and other coding agents register MCP servers in their settings.
  • Claude Desktop reads MCP servers from its configuration file.
  • ChatGPT desktop can use MCP servers registered for its local tooling.

Desktop chat apps are where MCP matters most, because there's often no other way in. Some keep their conversations on the provider's servers, so a local memory can't learn from those chats, but it can still serve them everything your coding tools learned.

How do you set up an MCP memory server?

Register the server with each client, then check the model can see its tools.

  1. Install the server so it runs locally, over standard input and output.
  2. Register it in each client. Desktop apps and coding agents each keep a list of MCP servers in their settings; add one entry that starts the server.
  3. Restart the client and confirm the memory tools appear in its tool list.
  4. Ask a question only memory can answer, like "what did we decide about retries last week?", and check it called the tool.
  5. Add push for the basics, so the most important context doesn't depend on the model remembering to ask.

A typical client entry has the same shape everywhere: a name, the command that starts the server, and its arguments.

{
  "mcpServers": {
    "memory": {
      "command": "node",
      "args": ["/path/to/memory-server.mjs"]
    }
  }
}

The exact file and format differ by client; check its MCP documentation. A good memory layer does this registration for you, and only ever adds its own entry.

What should you watch for?

Four things: reach, cost, scope and secrets.

Keep it local

A local server over standard input and output is never reachable from the network. Don't expose memory over HTTP without strong auth.

Token cost

Every tool definition is sent with every request. Keep descriptions tight and results small and ranked.

Scope

Return memories from the current project first, so one client's details don't surface in another's work.

Secrets

Scrub keys and tokens before storage. Whatever the server returns is sent to the model provider.

Frequently asked questions

What is an MCP memory server?

A Model Context Protocol server that exposes long-term memory as tools such as recall and load-context, so any MCP client reads the same persistent memory.

How do I give Claude Desktop persistent memory?

Register a memory MCP server in Claude Desktop's MCP configuration. Claude can then recall past decisions; it can't learn from Desktop's own chats if they live server-side, but it gets everything your other tools learned.

What is the difference between push and pull memory?

Push puts context in front of the model automatically; pull (MCP) is searched only when the model asks. Use both.

Is a local MCP memory server secure?

Running locally over standard input and output keeps it off the network. Also scope it per project and scrub secrets before storage.

Does an MCP server cost tokens?

Yes: tool definitions on every request and every result the model reads. Keep both small.
