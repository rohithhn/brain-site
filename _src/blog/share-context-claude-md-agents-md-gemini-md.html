What are CLAUDE.md, AGENTS.md and GEMINI.md?

They're the same idea under three names: a plain Markdown file of instructions that an AI coding tool loads at the start of every session. Whatever you write there (your stack, conventions, decisions, "never do X") is in the model's context before you type your first message.

The catch is that each tool looks for its own file, in its own folder. If you use more than one tool, your context is split across several files that know nothing about each other.

Two details trip people up. Gemini CLI and Antigravity share one file, so edit it once for both. And Cursor has no global file on disk: file-based context reaches it one repository at a time.

How do I give every tool the same context?

Keep one source of truth and copy it into every file the tools read.

  1. Write it once. Keep a single shared notes file with your conventions and the decisions every tool should know.
  2. Copy or link it into each global file: ~/.claude/CLAUDE.md, ~/.codex/AGENTS.md and ~/.gemini/GEMINI.md.
  3. Add a per-repo AGENTS.md for Cursor, and for anything specific to that project.
  4. Register an MCP memory server for tools that don't read files, like Claude Desktop and ChatGPT desktop.
  5. Update all of them every time something changes. That last step is where it usually falls apart.

What should go in these files?

Only what should shape every session, kept short. These files are read at the start of every conversation, so every line costs tokens every time.

Settled decisions

"Sessions live in SQLite, not Redis." The things a tool would otherwise confidently undo.

Conventions

Package manager, test command, branch rules, code style the linter doesn't catch.

Hard-won fixes

The bug that took an afternoon, and the one-line lesson that prevents it next time.

Not: full histories

Long logs and old chats belong behind search, not in the always-loaded file.

Not: secrets

No API keys or tokens. These files are plain text and often get committed.

Not: stale notes

A wrong instruction is worse than none. Prune what no longer holds.

Where does the manual approach break down?

It depends on you remembering to update four or more files after every decision.

  • The files drift. One tool gets the new decision, the others keep the old one.
  • They grow. Without pruning, the always-loaded context bloats and every session gets slower and more expensive.
  • Nothing is captured automatically. The decision you made in chat on Monday only reaches the files if you write it down.
  • Cursor needs a file in every repository, so new projects start blank.

Push vs pull: what's the difference?

Push puts context in the file a tool always loads. Pull lets the model search for context when it decides it needs it. You want both.

Push (instructions file)Pull (MCP server)
When it's usedEvery session, automaticallyWhen the model asks for it
Best forShort, always-true contextOlder or detailed memory
Token costPaid every sessionOnly when searched
Works in desktop chat appsNoYes

Frequently asked questions

What is the difference between CLAUDE.md, AGENTS.md and GEMINI.md?

They do the same job for different tools: Markdown instructions loaded at the start of a session. Claude Code reads CLAUDE.md, Codex and Cursor read AGENTS.md, and Gemini CLI and Antigravity read GEMINI.md.

Where does Claude Code read CLAUDE.md from?

From a global file at ~/.claude/CLAUDE.md for every project, and from a CLAUDE.md inside a repository for that project.

Do Gemini CLI and Antigravity use the same file?

Yes. Both read the global ~/.gemini/GEMINI.md, so whatever you write there reaches both.

Does Cursor have a global instructions file?

Not on disk. Its global rules live inside the app, so file-based context reaches Cursor through an AGENTS.md in each repository.

Can Claude Desktop or ChatGPT desktop read these files?

No. Neither loads a local instructions file. They can reach shared memory over an MCP server, configured in claude_desktop_config.json for Claude Desktop and in ~/.codex/config.toml for the ChatGPT desktop app.

How do I keep all these files in sync?

By hand: keep one source text and copy or link it into each file after every change. Automatically: a memory layer like Agentic Brain writes the same short briefing into every file inside its own markers and never touches text you wrote yourself.
