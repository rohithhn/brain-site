What is an AI memory layer?

An AI memory layer is software that gives a stateless AI model long-term memory. It watches conversations, pulls out what matters, stores it, and brings the relevant parts back into the model's context in later sessions.

Large language models don't remember anything between sessions on their own. Every new chat starts with an empty context window. A memory layer is the piece that decides what carries forward: a user's preferences, a project's decisions, the fix for a bug solved last month. It's quickly becoming a standard part of how AI agents and assistants are built.

Why do AI agents need long-term memory?

Because an agent without memory starts from zero every time. It can't build on yesterday's work, learn your preferences, or avoid mistakes it already made.

Continuity

Pick up where you left off instead of re-explaining the project, the codebase or the customer.

Personalisation

Remember preferences, tone and constraints without being told every session.

Fewer repeated mistakes

Keep the lesson from what went wrong, so the agent doesn't undo a settled decision.

Lower token cost

Send the model a few relevant memories instead of an entire history.

Better answers

The right fact in context beats a huge context full of noise.

Work across tools

One memory can follow you between assistants, apps and devices.

Context window vs RAG vs memory layer: what's the difference?

They solve different problems, and they're often confused.

Long context windowRAGMemory layer
What it doesLets the model read more at onceRetrieves from fixed documentsLearns from the interaction itself
Lasts across sessionsNoOnly the documentsYes
Updates itselfNoWhen you re-indexWrites, updates and forgets
Token cost per answerHigh, grows with historyModerateLow: only what's relevant
Knows your preferencesOnly if pasted inRarelyYes

In practice they work together: a memory layer chooses what goes into the context window, and can use retrieval techniques to find it. Deciding what fills that window, step by step, is context engineering.

What are the types of AI agent memory?

Agent memory is usually split the way human memory is: short-term working memory, and three kinds of long-term memory.

  1. Working (short-term) memory. What's in the context window right now: the current conversation and task.
  2. Episodic memory. What happened: past conversations, sessions and events, in order. "Last Tuesday we migrated the database."
  3. Semantic memory. What's true: facts, decisions and preferences distilled from many episodes. "This project uses SQLite for sessions."
  4. Procedural memory. How to do things: workflows, habits and lessons learned. "Run migrations before seeding in CI."

A good memory layer turns episodes into semantic and procedural memory over time, instead of just storing transcripts.

How does an AI memory layer work?

Most memory layers run the same loop: capture, extract, store, retrieve and inject.

  • Capture the raw material: messages, tool calls, outcomes.
  • Extract what's worth keeping: facts, decisions, preferences, fixes.
  • Store and consolidate: merge duplicates, update facts that changed, and forget what's stale. This is where many systems quietly fail.
  • Retrieve what's relevant to the current task, ranked by relevance and usefulness.
  • Inject it into the model's context, within a small token budget.

The hard parts are consolidation and retrieval: keeping memory accurate as facts change, and finding the right few memories among thousands.

Vector memory vs graph memory: which is better?

Neither wins outright. Each fits a different kind of question.

Vector memoryGraph memory
How it storesText chunks as embeddingsEntities and their relationships
Good atFinding similar wordingMulti-step, relational questions
Weak atExact terms, names, relationshipsCost and complexity to build and maintain
SetupSimpleHeavier

Many strong systems are hybrids: plain keyword search for exact terms, vectors for meaning, and a re-ranking step on top. Don't pick an architecture on fashion. Measure it.

How do you benchmark AI memory?

Use public long-term memory benchmarks, and measure cost and speed alongside accuracy.

LongMemEval

Questions over long chat histories, testing single facts, updates, time, preferences, multi-session reasoning and knowing when to say "I don't know".

LoCoMo

Questions over very long multi-session conversations: single-hop, multi-hop, temporal and open-domain.

Tokens per answer

How much the model has to read to answer. Lower is cheaper and usually faster.

Latency

How long retrieval adds before the model can respond.

Evidence recall

Did the right memory reach the model at all? Answers can't beat retrieval.

Your own history

Benchmarks are a start. Test on questions about your real work too.

A useful baseline: giving the model the whole conversation. A memory layer should beat it on accuracy while reading far fewer tokens. On LoCoMo, ours scores 81.8 against 72.9 for the full conversation and 68.4 for the best published memory product, reading about 86% fewer tokens. On LongMemEval-S it answers 94.2% of 500 questions correctly.

LoCoMo comparison figures come from a widely cited 2025 published study with a different answering and judging model, so read them as direction, not a like-for-like race.

Hosted memory API or self-hosted memory?

A hosted memory API is fastest to start. Self-hosted memory keeps your data, your costs and your future in your hands.

Hosted memory APISelf-hosted / open source
SetupSign up, add a keyInstall and run it yourself
Where data livesThe vendor's serversYour machine or your cloud
Who can read itVendor infrastructureOnly you
PricingPer seat or per API callFree or your own infra cost
Lock-inExport if offeredYour data, your format
OperationsHandled for youYours to run

For personal projects and quick prototypes, hosted can be the right call. For source code, customer data or anything you'd rather not upload, owning the memory matters more than saving setup time.

How do I choose an AI memory layer?

Ask these ten questions before you commit.

  1. Accuracy: what does it score on public benchmarks, and against which baseline?
  2. Token cost: how much does the model read per answer?
  3. Speed: how much latency does retrieval add?
  4. Updates: what happens when a fact changes? Does the old one get replaced?
  5. Forgetting: can stale or wrong memories be removed, by you and automatically?
  6. Visibility: can you see and edit everything it remembers?
  7. Privacy: where is the data stored, and who holds the encryption key?
  8. Portability: can you export everything in an open format?
  9. Reach: does it work across the tools and agents you actually use?
  10. Proof: is every change measured, or does it just "feel smarter"?

Frequently asked questions

What is an AI memory layer?

Software that gives a stateless AI model long-term memory. It extracts what matters from conversations, stores it, and retrieves the relevant parts into the model's context in later sessions.

Why do AI agents need long-term memory?

Models are stateless, so every session starts empty. Without memory an agent forgets decisions and preferences, repeats mistakes, and needs context explained again, which wastes time and tokens.

Is a bigger context window the same as memory?

No. A context window is how much a model can read in one session; memory decides what carries over to the next. Filling a huge window with full history is slow and expensive, and accuracy often drops as context grows.

What's the difference between RAG and AI memory?

RAG retrieves from a fixed set of documents. A memory layer learns from the interaction itself: it writes new memories, updates outdated ones and forgets what no longer matters.

Vector memory or graph memory: which is better?

Vector memory is simple and good at similar wording; graph memory captures relationships and helps multi-step questions but costs more to build. Many systems combine keyword search, vectors and re-ranking.

How do you benchmark AI memory?

Use public benchmarks such as LongMemEval and LoCoMo, which score answers to questions about long histories. Also measure latency, tokens per answer, and whether the right evidence was retrieved.

Should I use a hosted memory API or self-hosted memory?

Hosted is fastest to start. Self-hosted or open-source memory keeps data under your control, avoids per-call pricing and lock-in, and suits code and personal data. Decide based on who should be able to read your memory.
